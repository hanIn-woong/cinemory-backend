## C-1. 화면 기본 구성 — ✅ B′ (한 화면 스크롤 + 지도 미리보기)

```
CineMap 탭 (세로 스크롤)
├── 박스오피스        가로 목록 5편 + "더보기" → 전체 10위 화면
├── 내 주변 극장
│   ├── 지도 미리보기   마커 표시, 끌기·확대 꺼짐 — 탭하면 전체 화면 지도
│   ├── 가까운 극장 5곳
│   └── [지도에서 모두 보기]
└── (전체 화면 지도)  지도 + 바텀시트 목록 + 극장 카드 [예매하기] [길찾기]
```

| 결정 | 이유 |
|---|---|
| 원안 B(한 화면) 유지 — 사용자 의도 | 박스오피스와 극장을 한눈에 |
| **지도는 미리보기(조작 불가)** | 스크롤 화면 안의 조작 가능한 지도는 **세로 스크롤과 지도 끌기가 충돌**한다(§13.2 위험도 "큼", Android WebView에서 심함). 미리보기는 탭만 받는다 |
| 탐색은 **전체 화면 지도** | 상단 탭안(A)에도 어차피 필요한 화면이라 추가 비용이 아니다 |
| 박스오피스 가로 목록 5 + 더보기 | 가로 스크롤은 세로 스크롤과 충돌하지 않는다 |
| **위치 권한은 미리보기 영역의 "내 위치로 보기"에서** | 처음엔 기본 위치(서울시청)로 보여 준다 — 박스오피스만 보는 사람은 권한 요청을 받지 않는다 |

- **기각 — A안(상단 탭 `박스오피스 | 내 주변 극장`)** — 충돌은 없지만 한눈에 보기를 잃는다. B′가 둘 다 얻는다.
- **기각 — 카카오 정적 지도 이미지로 미리보기** — 가볍지만 일 무료 1,000건 초과 시 건당 과금, 화면 진입마다 호출하는 구조와 맞지 않는다.

## C-2. 지도 API — ✅ 카카오 JS SDK + WebView

| 비교 | 카카오 JS + WebView (채택) | 네이버 네이티브 | 구글/애플 |
|---|---|---|---|
| 한국 지도 | 최상 | 최상 | ⚠️ 구글은 2026-02 고정밀 지도 반출 **조건부 허가**, 반영 시점 불확실 |
| 조작감 | WebView(초기 로딩 0.5~1.5초) | 네이티브, 최상 | 네이티브 |
| 계정 | **기존 카카오 디벨로퍼스 앱에 지도 활성화** | 네이버 클라우드 가입 + 결제수단 | 구글 클라우드 |
| 비용 | 계정에서 **처음 지도를 활성화한 앱에 무료 쿼터**(2026-07-21 정책) | 종량제, 모바일 무료 구간 미확인 | 월 크레딧 |
| 새 외부 의존 | 없음 (로그인과 같은 업체) | 네이버 추가 | 구글 추가 |

- **근거** — 새 업체·결제·약관 없음. B′ 구성이면 WebView의 최대 약점(제스처 충돌)이 미리보기에서 사라진다. CineMap은 일정이 밀리면
  가장 먼저 잘라 낼 기능(기획노트 "잘라낼 순서")이라 설정 비용이 작은 쪽이 맞다.
- **교체 경로 유지** — §13.3 격리 인터페이스. 네이버 네이티브로 바꾸는 비용 반나절~1일. Dev Client 전환(9/11)이 끝나 §13.4의
  "편도 전환" 비용도 사라졌다. 인터페이스에 **`interactive: boolean`**(미리보기 모드) 추가.
- **카카오 네이티브 SDK v2 기각** — 관리되는 RN 래퍼가 없어 네이티브 모듈을 직접 만들어야 한다.

**카카오 디벨로퍼스 설정 (사용자 작업)**

1. 기존 CineMory 앱에서 **카카오맵 활성화** — ⚠️ 무료 쿼터는 계정에서 처음 활성화한 앱에 붙는다. 다른 테스트 앱에서 먼저 켜지 않는다.
2. **JavaScript 키** 확인 + **Web 플랫폼 도메인 등록** — WebView가 로컬 HTML을 띄울 때의 `baseUrl`과 맞춘다(구현 단계 확인).
3. **REST API 키** 확인 — 백엔드 주소 → 좌표 변환(C-4-4)용. 서버에만 둔다.

## C-3. 극장 데이터 원천 — ✅ 행정안전부_문화_영화상영관 조회서비스

| 항목 | 내용 |
|---|---|
| 위치 | 공공데이터포털 **15154848** (REST, JSON/XML) |
| 범위 | 전국 자치단체 영화상영관 인허가 통합 |
| 갱신 | 일간 |
| 한도 | 개발 계정 일 10,000건 |
| 좌표 | **Bessel 중부원점 TM(EPSG:5174)만**, 위경도 없음. **빈 값인 행이 있다**(실측) |
| `totalCount` | **5,244** (2026-10-27, 폐업 포함) |

- **기각 — "한국문화정보원_전국 연극장 및 소극장 데이터"** — 연극 공연장이다.
- 기획노트 (5)의 *"EPSG:5174 → WGS84 변환 필수"* 가 이 데이터를 가리킨다.
- 기존 `TheaterSeedData` 주석의 *"전국영화상영관표준데이터 1행"* 은 이 원천으로 대체한다.

### C-3-1. ⚠️ 실측 — 응답 샘플 10건 (2026-10-27)

**① 한 행 = 극장이 아니라 상영관(관) 하나** — "롯데시네마 속초 1관"~"5관"이 각각 별도 행이다. 5,244는 상영관 수다.
그대로 넣으면 같은 자리 마커가 관 수만큼 겹친다. → **극장 단위로 묶는다**(C-4-2).

**② `MNG_NO`가 전국 고유가 아니다** — `CDFF4220002026000005`가 속초 5관과 검단아라 1관에 둘 다 있다. 자치단체마다 번호를 따로 매긴다.
원천 행 식별은 `OPN_ATMY_GRP_CD + MNG_NO`.

**③ 좌표 빈 행** — 검단아라 5개 관은 `CRD_INFO_X/Y`가 `""`. → **주소 → 좌표 변환이 기본**(C-4-4).

**④ 같은 극장의 관끼리 주소 상세가 다르다** — 검단아라 6관만 도로명 주소에 "18층"이 붙어 있다. 상세 주소로 묶으면 갈라진다.

### C-3-2. 사용할 필드

| 필드 | 예 | 용도 |
|---|---|---|
| `OPN_ATMY_GRP_CD` | `4231000` | 자치단체 코드 — 묶음 키의 일부 |
| `MNG_NO` | `CDFF4220002026000005` | 자치단체 안에서만 고유 |
| `BPLC_NM` | 롯데시네마 속초 3관 | 극장명 · 체인 판정 |
| `SALS_STTS_CD` / `SALS_STTS_NM` | `01` / 영업/정상 | **`01`만 적재** |
| `DTL_SALS_STTS_NM` | 영업중 | 참고 |
| `PRFRPLC_SHP_SE_NM` | 영화관 | 영업 형태 — 다른 값(자동차극장 등) 분포는 dryRun으로 확인 |
| `ROAD_NM_ADDR` | 강원특별자치도 속초시 중앙로121번길 28, 센텀마크빌딩 제엠-301호 (금호동) | 주소 · 묶음 키 · 좌표 변환 |
| `LOTNO_ADDR` | 강원특별자치도 속초시 금호동 473-235 센텀마크빌딩 | 도로명이 없을 때 대체 |
| `CRD_INFO_X` / `CRD_INFO_Y` | `339101.58` / `523440.60` | EPSG:5174, 마지막 대체 수단 |
| `DAT_UPDT_PNT` | 2026-10-08 21:10:40 | 향후 변경분 동기화(C-5) |

**쓰지 않는다** — 좌석 수 필드가 없다(`theater.seat_count`는 null). 층수·통로 폭·청소년실 등 인허가 항목은 화면 요구가 없다.

## C-4. 극장 적재 설계 — 🟡 초안 (B-9 해소)

### C-4-1. 입력 방식 — 파일이 아니라 API를 서버가 직접 호출

B-9의 *"멀티파트 업로드 vs 서버 파일"* 문제가 사라진다. KOFIC 박스오피스와 같은 구조다.

```
POST /api/admin/theaters/seed[?dryRun=true]
  TheaterSeedService (트랜잭션 없음)
   1. PublicDataTheaterClient — 전 페이지 순회 (numOfRows 100 → 약 53회)
   2. 영업 중(SALS_STTS_CD=01) + 영업 형태 필터
   3. 극장 단위 묶기 (C-4-2)        → 극장명 · 체인 · 상영관 수
   4. 좌표 결정 (C-4-4)             → 카카오 주소 검색 → 지번 → TM 변환
   5. dryRun이면 통계만 반환(C-4-6), 아니면 TheaterPersister(@Transactional) upsert
```

- HTTP 호출은 트랜잭션 밖, 저장만 별도 빈 — tmdb-sync 6-4 원칙.
- `global/infra/publicdata/PublicDataTheaterClient` — `tmdb`·`kofic`과 같은 위치. 타임아웃 connect 2s / read 5s.
- 키 — `publicdata.service-key`(운영 `PUBLICDATA_SERVICE_KEY`), `kakao.rest-api-key`(운영 `KAKAO_REST_API_KEY`). `cinemory.env.example`·런북 대응표에 추가.
  ⚠️ 공공데이터포털 키는 **Decoding 키를 쓰고 HTTP 클라이언트가 인코딩**하게 한다(Encoding 키를 넣으면 이중 인코딩).
- 실행 중 플래그 — 시드·resync·임베딩과 **분리**(호출 대상이 다르다). 실행 중이면 409 `SEED_ALREADY_RUNNING` 재사용 여부는 구현 시 판단.
- 감사 로그 `THEATER_SEED` (dryRun은 기록하지 않는다 — 쓰기가 없다).

### C-4-2. 극장 단위로 묶기 — **주소 기준**

| 후보 | 판정 |
|---|---|
| 극장명에서 "N관"을 떼고 묶기 | ⚠️ 이름이 지저분하다 — "IMAX관"·"4DX관"·"골드클래스" 등 "N관"이 아닌 관 이름, 표기 흔들림("CGV"/"씨지브이"). 떼는 규칙이 끝없이 늘어난다 |
| **도로명 주소의 "도로명 + 건물번호"로 묶기 (채택)** | 같은 극장의 관은 같은 건물에 있다. 상세(동·호·층·괄호)를 떼면 ④의 "18층" 차이도 흡수된다 |

```
묶음 키  = OPN_ATMY_GRP_CD + "|" + 주소 기준부
주소 기준부 = ROAD_NM_ADDR에서 첫 쉼표 앞 + 괄호 제거 → "강원특별자치도 속초시 중앙로121번길 28"
            (도로명이 비면 LOTNO_ADDR에서 번지까지)
```

| 묶은 극장의 값 | 결정 |
|---|---|
| `name` | 그룹 안 이름들을 정규화(C-4-3)한 뒤 **가장 많이 나온 값** |
| `chain_name` | 이름 앞부분 사전 매칭(C-4-3) |
| `screen_count` | **그룹의 행 수** (영업 중인 관 수) — 기존 컬럼에 그대로 |
| `seat_count` | null (원천에 없음) |
| `address` | 주소 기준부 (상세 제외) |
| `source_code` | 묶음 키 |

- ⚠️ **한 건물에 극장이 둘**(쇼핑몰에 CGV·메가박스)이면 하나로 묶인다 — 드물 것으로 보지만 **dryRun이 "한 그룹 안에 체인이 둘 이상"인 경우를 따로 보고**한다.
  있으면 묶음 키에 체인을 추가한다.
- 스키마 — `theater.source_code varchar(30)`에 묶음 키가 들어가지 않는다 → **`varchar(255)`로 확장**(Flyway, 확장 마이그레이션).

### C-4-3. 극장명 정규화 · 체인 판정 — dryRun 후 확정

**시작 규칙**

1. 앞뒤 공백 제거, 연속 공백 1개
2. **끝의 관 표기 제거** — `\s*(제)?\d+(관|상영관)$`, 그리고 끝 토큰이 사전의 특별관(IMAX·4DX·SCREENX·골드클래스·샤롯데·부티크·리클라이너 등)+"관"이면 제거
3. 그룹 안 최빈값을 극장명으로

**체인 사전 (시작)**

| `chain_name` | 이름 앞부분 |
|---|---|
| CGV | `CGV`, `씨지브이` |
| 롯데시네마 | `롯데시네마` |
| 메가박스 | `메가박스`, `MEGABOX` |
| 씨네Q | `씨네Q`, `씨네큐` |
| 기타 | 그 외 (독립·예술영화관 등) |

- 규칙이 *맞는지는* 샘플 10건으로 알 수 없다 → dryRun의 "정규화 후에도 이상한 이름" 목록으로 보완한다.

### C-4-4. 좌표 결정 — 카카오 주소 검색 우선

| 순서 | 방법 | 비고 |
|---|---|---|
| 1 | **주소 기준부**를 카카오 로컬 **주소 검색**(REST) → WGS84 | **지도와 같은 카카오 데이터라 마커가 지도 위 건물에 정확히 맞는다** |
| 2 | 1 실패 → `LOTNO_ADDR` 기준부로 주소 검색 | |
| 3 | 2 실패 + TM 좌표 있음 → **EPSG:5174 → EPSG:4326** 변환(`proj4j`) | ⚠️ Bessel 타원체 변환 파라미터가 틀리면 **수백 m씩 어긋나도 오류 없이 저장**된다 — 단위 테스트로 알려진 지점 1곳 이상을 고정한다 |
| 4 | 모두 실패 | 적재하지 않고 `WARN` + dryRun 실패 목록 |

- 호출량 — 극장 수(수백) × 1~2회, 1회성. 카카오 로컬 무료 쿼터 안.
- 주소 → 좌표는 **그룹당 1회**(관마다 하지 않는다).

### C-4-5. 저장 정책 — 기존 "있으면 건너뛰기"를 바꾼다

기존 `TheaterSeedService.seedAll`은 *"이미 있는 `source_code`는 건너뛴다(극장 속성은 거의 안 변한다)"* 였다. 공공 API는 매일 갱신되고
**관 증설·폐관이 `screen_count`·존재 여부를 바꾼다.** → **upsert**(있으면 이름·체인·주소·좌표·관 수 갱신)로 바꾼다.
`Theater`에 `updateFromSource(...)` 하나를 연다(Setter 금지 원칙 — 의도가 드러나는 메서드 하나).

- **폐업 처리는 C-5에서** — `theater`를 FK로 참조하는 테이블이 없다(확인 2026-10-27). 원천에서 사라진 극장을 삭제해도 무결성 문제는 없다.

### C-4-6. dryRun — 적재 전에 실측한다

`POST /api/admin/theaters/seed?dryRun=true` → 저장 없이 200 `TheaterSeedReport`.

| 항목 | 용도 |
|---|---|
| 전체 행 · 영업 중 행 · 묶은 극장 수 | 규모 |
| `PRFRPLC_SHP_SE_NM`별 건수 | 영업 형태 필터 결정(자동차극장 등) |
| 체인별 극장 수 (`기타` 포함) | 사전 보완 |
| **정규화 후 이름이 그룹 안에서 갈린 그룹** 상위 50 | 정규화 규칙 보완 |
| **한 그룹에 체인이 둘 이상**인 그룹 | 묶음 키 보완 여부 |
| 관 수 분포 (1관 극장 수 등) | 소규모 상영 시설 판단 |
| 좌표 결정 경로별 건수 (주소 / 지번 / TM / 실패) + 실패 목록 | 좌표 품질 |
| 샘플 20개 극장 (최종 값) | 눈으로 확인 |

**한 번 만들어 두면 재동기화 전 검증 도구로 계속 쓴다.**
